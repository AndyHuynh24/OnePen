## Quick Reference

### ✅ PUSH These
| Category | Examples |
|----------|----------|
| Source code | `*.py`, `*.js`, `*.html`, `*.css` |
| Configuration | `config.yaml`, `firebase.json`, `pyproject.toml` |
| Requirements | `requirements.txt`, `package.json` |
| Documentation | `README.md`, `docs/` |
| Tests | `tests/`, `pytest.ini` |
| CI/CD | `.github/workflows/` |
| Small assets | Icons, small images for UI |
| Raw data (if small) | `data/raw/` (< 50MB total) |
| Deployed models | `app/tfjs/` (models needed for the app) |

### ❌ IGNORE These
| Category | Examples | Why |
|----------|----------|-----|
| Virtual environments | `.venv/`, `node_modules/` | Huge, reproducible |
| Compiled files | `__pycache__/`, `*.pyc` | Auto-generated |
| ML artifacts | `mlruns/`, `outputs/`, `*.keras` | Large, reproducible |
| Processed data | `data/processed/`, `*.npz` | Regenerate from raw |
| Secrets | `.env`, `*credentials*.json` | **SECURITY RISK!** |
| IDE settings | `.vscode/`, `.idea/` | Personal preference |
| OS files | `.DS_Store`, `Thumbs.db` | Useless clutter |
| Logs | `*.log`, `logs/` | Auto-generated |
| Cache | `.cache/`, `.pytest_cache/` | Temporary |

## The Golden Rules

### Rule 1: Never Commit Secrets 🔐
```
❌ NEVER commit:
   - .env files
   - API keys
   - Passwords
   - Service account JSON files
   - Private keys (*.pem, *.key)
```

**If you accidentally commit a secret:**
1. Revoke the key immediately
2. Remove from git history: `git filter-branch` or BFG Repo-Cleaner
3. Generate new credentials

### Rule 2: If It Can Be Generated, Don't Commit It 🔄
```
❌ Don't commit:
   - __pycache__/     → Generated when Python runs
   - node_modules/    → Generated by npm install
   - .venv/           → Generated by python -m venv
   - data/processed/  → Generated from data/raw/
   - mlruns/          → Generated during training
   - *.pyc            → Compiled Python
```

### Rule 3: If It's Large, Think Twice 📦
```
Before committing large files, ask:
   - Can this be regenerated? → Don't commit
   - Is this needed for deployment? → Maybe commit
   - Is this > 100MB? → Use Git LFS or don't commit
```

### Rule 4: Source Code = Always Commit 💻
```
✅ Always commit:
   - All .py, .js, .html, .css files
   - Configuration files
   - Documentation
   - Tests
```

## What to PUSH (Commit)

### 1. Source Code
```
✅ PUSH:
├── src/                    # Python source code
│   └── **/*.py
├── app/                    # Web app code
│   ├── *.html
│   ├── *.js
│   ├── *.css
│   └── assets/            # Small UI assets
├── scripts/               # Utility scripts
│   └── *.py
└── tests/                 # Test files
    └── *.py
```

### 2. Configuration Files
```
✅ PUSH:
├── config/
│   └── config.yaml        # ML configuration
├── firebase.json          # Firebase config
├── pyproject.toml         # Python project config
├── pytest.ini             # Test config
├── requirements.txt       # Python dependencies
├── package.json           # Node dependencies (if any)
└── Makefile              # Build commands
```

### 3. Documentation
```
✅ PUSH:
├── README.md
├── docs/
│   ├── CICD_GUIDE.md
│   └── GIT_GUIDE.md
├── assets/                # Documentation images
│   └── architecture.png
└── notebooks/            # Jupyter notebooks (optional)
    └── *.ipynb
```

### 4. CI/CD
```
✅ PUSH:
└── .github/
    └── workflows/
        └── ci-cd.yml
```

### 5. Deployed/Production Models
```
✅ PUSH (only models needed for the app to work):
└── app/
    └── tfjs/              # TensorFlow.js models for web app
        ├── model.json
        └── *.bin
```

### 6. Raw Data (if small)
```
✅ PUSH (if total < 50MB):
└── data/
    └── raw/               # Original training data
        ├── contributor1/
        └── contributor2/
```

**If data is large (> 50MB):**
- Use Git LFS (Large File Storage)
- Or store externally (S3, Google Drive) and document how to download

## What to IGNORE (Never Commit)

### 1. Virtual Environments (~500MB-2GB)
```
❌ IGNORE:
├── .venv/
├── venv/
├── env/
└── node_modules/
```
**Why:** Huge, platform-specific, easily recreated with `pip install -r requirements.txt`

### 2. Python Compiled Files
```
❌ IGNORE:
├── __pycache__/
├── *.pyc
├── *.pyo
└── *.so
```
**Why:** Auto-generated when Python runs

### 3. ML Training Artifacts (~100MB-10GB+)
```
❌ IGNORE:
├── outputs/               # Training outputs
├── checkpoints/           # Model checkpoints
├── wandb/                 # Weights & Biases
├── tensorboard_logs/      # TensorBoard
├── *.keras                # Keras models
├── *.h5                   # HDF5 models
├── *.pt                   # PyTorch models
├── *.ckpt                 # Checkpoints
└── *.tflite               # TFLite models
```
**Why:** Large, reproducible by retraining

### 4. Processed Data
```
❌ IGNORE:
├── data/processed/
│   ├── *.npz              # NumPy arrays
│   ├── *.pkl              # Pickled data
│   └── *.json             # Large JSON files
└── data/augmented/
```
**Why:** Regenerate from raw data using your scripts

### 5. Secrets & Credentials 🔐
```
❌ NEVER COMMIT:
├── .env
├── .env.local
├── .env.production
├── *credentials*.json
├── *serviceAccount*.json
├── firebase-adminsdk*.json
├── *.pem
└── *.key
```
**Why:** **CRITICAL SECURITY RISK!** Anyone with repo access gets your secrets

### 6. IDE & Editor Settings
```
❌ IGNORE:
├── .vscode/
├── .idea/
├── *.swp
├── *.sublime-project
└── .spyderproject
```
**Why:** Personal preference, can cause conflicts

### 7. OS Files
```
❌ IGNORE:
├── .DS_Store              # macOS
├── Thumbs.db              # Windows
├── desktop.ini            # Windows
└── ._*                    # macOS
```
**Why:** Useless clutter

### 8. Logs & Cache
```
❌ IGNORE:
├── logs/
├── *.log
├── .cache/
├── .pytest_cache/
├── htmlcov/               # Coverage reports
└── .coverage
```
**Why:** Auto-generated, temporary

### 9. Firebase Cache
```
❌ IGNORE:
├── .firebase/
└── .firebaserc            # Local Firebase config
```
**Why:** Auto-generated, contains local paths

## How to Check Before Pushing

### 1. See What Will Be Committed
```bash
# See all files that will be pushed
git status

# See what's being tracked
git ls-files

# See what's being ignored
git status --ignored
```

### 2. Check File Sizes
```bash
# Find large files in your repo
find . -type f -size +10M -not -path "./.git/*" -not -path "./.venv/*"

# Or on Windows (Git Bash)
find . -type f -size +10M | grep -v ".git" | grep -v ".venv"
```

### 3. Dry Run Before Pushing
```bash
# See what would be added
git add --dry-run .

# Or add and then check
git add .
git status
# If something wrong, unstage:
git reset HEAD
```

### 4. Check for Secrets
```bash
# Search for potential secrets
grep -r "password" --include="*.py" --include="*.js" .
grep -r "api_key" --include="*.py" --include="*.js" .
grep -r "secret" --include="*.py" --include="*.js" .
```

## Common Mistakes

### Mistake 1: Committing .env
```bash
# If you accidentally committed .env:
git rm --cached .env
echo ".env" >> .gitignore
git commit -m "Remove .env from tracking"

# Then revoke and regenerate all secrets in that file!
```

### Mistake 2: Committing node_modules or .venv
```bash
# Remove from git but keep locally:
git rm -r --cached node_modules/
git rm -r --cached .venv/
git commit -m "Remove node_modules and .venv from tracking"
```

### Mistake 3: Committing Large Files
```bash
# Find the large files
git rev-list --objects --all | \
  git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(rest)' | \
  awk '/^blob/ {print $3, $4}' | \
  sort -rn | head -20

# Remove large file from history (use BFG or git filter-branch)
```

### Mistake 4: Not Using .gitignore From the Start
```bash
# Add .gitignore and remove already-tracked ignored files
git add .gitignore
git rm -r --cached .
git add .
git commit -m "Add .gitignore and clean up tracked files"
```

## Summary Checklist

Before pushing, verify:

- [ ] No `.env` or credential files
- [ ] No `node_modules/` or `.venv/`
- [ ] No large files (> 50MB)
- [ ] No `mlruns/` or `outputs/`
- [ ] No `__pycache__/`
- [ ] `.gitignore` is properly configured
- [ ] All source code is included
- [ ] `requirements.txt` is up to date
- [ ] README is updated
